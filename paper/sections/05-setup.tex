\section{Experimental setup}
\label{sec:setup}

\paragraph{Workflows.}
We study three workflows of increasing size (details in Appendix~\ref{app:workflows}).
\textbf{W1} is a single tool-calling agent that answers 80 HotpotQA questions
\citep{yang2018hotpotqa} with live Wikipedia search and page reading. \textbf{W2} is a
customer-service agent on 40 $\tau$-bench retail tasks \citep{yao2024taubench}, with 16 stateful
tools over a shop database and an LLM-simulated customer. \textbf{W3} is a five-role research
pipeline (planner, researchers, writer, reviewer, reviser, plus an unscored log summary) on 80
FRAMES questions \citep{krishna2024fact}. All nodes run on \texttt{gemini-3.5-flash-lite}.

\paragraph{Variants.}
W1 has 18 variants: the base, six edits, nine mutants and two model swaps. W2 has eleven: the
base, four edits (preambles), four mutants and two model swaps. W3 has thirteen in two focus
groups: the writer (three edits, two mutants, a model swap) and the planner (the same), sharing the
base. Edits were written by a separate LLM instance asked for plausible improvements; mutants are
deliberate breakages that the full workflow should catch.

\paragraph{Miniatures.}
For each workflow we build miniatures from the operators of Table~\ref{tab:operators}, choosing
for each workflow the ones its structure admits. Miniatures that ran after the budget
was known (W1 simulation, re-run and short outputs; W2 except the fused conversation) use a core
set of ten (W1) and eight (W2) variants that keeps every clearly broken one; all W1 comparisons in
Table~\ref{tab:main} use the W1 core set.
W1 tests simulated tools (pure and cache-first), short tool outputs, fewer tasks and a fused
agent loop; W2 tests a cheaper simulated customer, simulated shop tools and a fused conversation; W3
tests, for the writer, replaying the planner and research (alone, and with slicing and early
stopping) and stubbed researchers, and, for the planner, simulated researcher tools, stubbed
researchers (alone and with slicing and early stopping) and the whole pipeline as one call.

\paragraph{Ground truth and the noise ceiling.}
Every variant runs once on every task under the full workflow. A second full run with fresh samples
gives the noise ceiling, for W1 and for W3's writer group (budget did not allow one for W2 or
W3's planner group).

\paragraph{Statistics.}
Scores are task means. Pairwise differences use paired standard errors over tasks; a pair is
\emph{clear} when its full-workflow difference exceeds two standard errors. A mutant is
\emph{caught} by the full workflow when it scores below the base by more than two standard errors,
and by a miniature when the miniature's difference points the same way (and, more strictly, is
itself beyond two standard errors). Costs are measured from the providers' token counts and
published prices; latencies are wall-clock per call, reported as medians per run.

\paragraph{Budget.}
The whole study, including two complete ground truths for W1 (one per model family), cost
\todo{\$X} in API calls under a hard cap enforced before every call. Judging used a Claude
subscription and no API spend.
