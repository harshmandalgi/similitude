\section{Related work}

\paragraph{Cheaper evaluation by fewer items.}
Benchmark compression chooses a small set of items whose scores predict the full benchmark:
anchor points \citep{vivek2023anchor}, item-response models \citep{polo2024tinybenchmarks,kipnis2024metabench}, and
compute-aware subsets \citep{perlitz2023efficient}. For agents, keeping tasks of intermediate difficulty
preserves rankings \citep{ndzomga2026efficient}, scores can be predicted from cheaper non-agent items
\citep{song2026pace}, and runs can be stopped once their outcome is predictable \citep{shi2026earlyeval}. These
methods shrink the \emph{test set} or the \emph{run length}; we shrink the \emph{system under test},
and the two combine.

\paragraph{Simulated tools, users and environments.}
LLMs can emulate tools to expose risky agent behaviour \citep{ruan2023identifying}, stabilise flaky APIs
\citep{guo2024stabletoolbench,guo2025stabletoolbenchmirrorapi}, stand in for a stateful backend \citep{chuang2026toward}, or play
the user \citep{yao2024taubench,barres2025tau2bench}; simulators built from recorded real calls are far more
faithful than those built from documentation \citep{wang2026mcppersona}. Whole benchmarks now run in
simulated environments \citep{hu2026occubench}, and production teams screen agent versions in simulation
before release \citep{alcoba2026screen}. The evidence also warns: the choice of user simulator moves success
rates by up to nine points \citep{seshadri2026lost}, simulated users are an ``easy mode''
\citep{zhou2026mind}, faults in how tools behave hurt agents far more than noise in what they return
\citep{zhou2026when}, simulators fail when several things change at once \citep{liu2026envsimbench}, and
the choice of simulator model can reorder agent rankings \citep{hu2026occubench}. None of these measures
whether decisions about variants of an existing workflow survive the simulation, which is our
question.

\paragraph{Cheap proxies whose decisions transfer.}
Small models predict which pretraining data wins at scale \citep{magnusson2025datadecide,liu2024regmix}; robot
policies evaluated in simulation can be ranked like real ones, measured by rank-violation metrics
we adopt \citep{li2024evaluating}. Compound-AI optimisers search on a cheap model and deploy on a strong one
\citep{agrawal2025gepa,zhang2024aflow,hu2024automated,oved2026optimize}, learn local rewards aligned with the global score
\citep{wu2025optimas}, or predict a design's score without running it \citep{shang2024agentsquare}. A single
agent can replace a homogeneous multi-agent workflow \citep{xu2026rethinking}, while merging a refinement
chain into one prompt lets the model fake the refinement \citep{sun2024prompt}. We study these moves as
\emph{evaluation} shortcuts and measure what they preserve.

\paragraph{Replay and test reduction.}
Recording agent runs and replaying chosen steps supports regression testing \citep{chawla2026chronicle}. Our
operators borrow from software testing more broadly: test doubles, program slicing
\citep{weiser1984program}, mutation testing \citep{jia2011analysis}, and above all test-case reduction, which
shrinks an input while an ``interestingness'' check still passes \citep{zeller2002simplifying}; we shrink a
workflow while its evaluation still makes the same decisions. Multi-fidelity methods combine many
cheap evaluations with a few expensive ones \citep{peherstorfer2018survey,li2018hyperband}, a natural use for
validated miniatures.
