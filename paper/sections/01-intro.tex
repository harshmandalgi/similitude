\section{Introduction}
\label{sec:intro}

Teams that build agent workflows change them often. A change can be a new prompt, a new model or a
new tool. Before a team keeps a change, it must know if the change makes the workflow better. The
usual method is a full evaluation: the team runs the full workflow on a set of tasks and compares
the scores. For an agent workflow, this is slow and costly, because one task can need tens of model
calls and tool calls. Thus, teams test few changes, and they trust results that contain much noise.

In engineering, this problem is old. Engineers test a scale model of a ship or a wing before they
build the real object. The theory of \emph{similitude} tells them when the results of the model are
also correct for the real object \citep{buckingham1914physically}. We ask the same question for
agent workflows: when does a small, cheap copy of a workflow give the same results as the full
workflow?

We do not ask the miniature for the same scores. A miniature can give lower scores and still be
useful. We ask it for the same \emph{decisions}. A decision is the answer to one question: of two
variants of the workflow, which one is better? If the miniature and the full evaluation pick the
same winners, a team can use the miniature to test its changes.

This paper gives four contributions:
\begin{itemize}
  \item A definition of validity for a miniature, based on decisions, with a check against a noise
  ceiling (Section~\ref{sec:system}).
  \item \sys{}, a system that applies thirteen shortcuts to a workflow, with no change to its
  code (Section~\ref{sec:system}).
  \item A study of sixteen miniatures of three workflows, with about 17{,}700 runs
  (Sections~\ref{sec:setup} and~\ref{sec:results}).
  \item Six rules that tell a team which shortcut to use for each part of a workflow
  (Section~\ref{sec:rules}).
\end{itemize}

The main results are positive. Simulated tools kept 90--100\% of the clear decisions when a model
can know the answers of the tool. Replay of the steps that do not change gives the same outputs, at
0.21$\times$ the cost. A quarter of the tasks kept 85\% of the clear decisions at 0.20$\times$ the
cost. The noise ceiling also found a full evaluation that did not agree with itself. Without this
check, a team can reject a correct miniature by mistake.
